# 📦 进销通 Jinxiao ERP v2.0 Pro

运行在 **Cloudflare Workers** 上的企业级全链路进销存与二级分销管理系统：全球边缘运行、零服务器维护，数据存 **D1**（SQLite），商品实拍图与全量备份存 **R2**。

## 🚀 v2.0 核心重构与 BUG 修复说明

### 1. 已修复的 13 项关键缺陷（v1.0.0 审计）
1. **修复全站双重 `layout()` 嵌套渲染 BUG**：v1.0.0 中 `src/views/*.ts` 内部已调用 `layout()`，而 `src/routes/*.ts` 又外包了一层 `layout()`，导致全站所有页面出现双层 `<html><body>`、双侧边栏、双顶栏，且 `app.js` 被加载执行两次（点击一次「添加商品」新增两行、二次确认弹窗触发两次）。v2.0 已彻底解耦视图组件与外层布局。
2. **修复初始化/注册/改密永远报「两次密码不一致」的阻断级 BUG**：表单输入框名为 `confirm_password`，而后端读取 `fields.confirm`，导致无法完成初始化、无法注册、无法改密。现已全面对齐并兼容。
3. **补全商品分类「重命名与排序」路由（`POST /categories/:id/rename`）**：修复原版点击分类重命名直接报 404 的问题，并支持分类排序权重调整与关联商品数展示。
4. **修复筛选与分页参数名不一致导致筛选失效的 BUG**：统一商品分类（`category_id` / `categoryId`）、库存流水（`product_id` / `productId`）、分佣管理（`sales_id` / `salesId`）参数解析。
5. **修复同单多行重复商品绕过库存校验及流水断链 BUG**：在采购、销售、退货及作废回滚中按商品实时递推运行态库存，杜绝拆行超卖及 `before_qty` → `after_qty` 断链，并采用**加权平均法**动态更新商品进货成本。
6. **补全商品建档「期初库存」流水（`initial_in`）**：新建商品录入期初库存 > 0 时自动写入期初入库流水，确保库存台账从 0 到当前值 100% 闭环可追溯。
7. **落地客户「赊账授信额度（`credit_limit`）」硬性风控与欠款补收核销**：开单时自动核算客户当前累计欠款 + 本单欠款是否超授信额度；在销售单详情页新增「欠款补收核销（`POST /sales/:id/pay`）」。
8. **新增销售退货单原单校验与作废回滚（`POST /returns/:id/void`）**：关联原销售单退货时自动校验原单商品与可退数量，支持退货单作废回滚，并修复经营报表中退货汇总未过滤 `status='done'` 及毛利未扣除整单优惠的偏差。
9. **修复用户管理与销售团队字段丢失及层级越权**：修复新增销售员丢失手机号、编辑用户无法修改角色与状态、二级销售仍能看到「新增销售员」按钮、以及将有下属的一级主管直接降级导致树断裂的问题。
10. **修复个人中心会话注销水平越权漏洞（IDOR）与缺失的 CSRF 校验**：`POST /profile/sessions/:id/revoke` 严格限定 `user_id` 归属，并为批量结算、立即备份、踢出其他设备补全 CSRF 令牌校验与操作按钮。
11. **修复东八区（UTC+8）跨日统计错位**：14 天销售趋势图改用 `datetime(created_at, '+8 hours')` 聚合，修复北京时间 00:00~08:00 订单被算入前一天的 BUG。

### 2. 企业级 UI 全面重构亮点
- **现代 SaaS 视觉体系**：采用高对比度 Slate & Royal Blue 企业级配色，内置 **深浅色主题切换（🌓 Dark Mode）**。
- **双栏品牌认证中心**：登录、初始化、客户注册与密保找回采用双栏沉浸式卡片布局。
- **分组侧边导航 + 顶栏快捷操作区**：支持实时低库存角标提醒、一键开单/入库快捷入口与个人中心直达。
- **POS 级智能开单与商业凭证打印**：实时联动计算「商品小计 - 优惠折扣 = 折后应收 / 挂账欠款」，支持一键填入全额实收；单据详情页内置 `@media print` 商业凭证打印样式，一键打印 A4 出入库单。

## 🛒 v2.1 订货链路增强（购物车化改造）

### 1. 商品目录「加入购物车」
- 客户在 `/catalog` 的每张商品卡下方可直接填写数量并点「🛒 加入购物车」，缺货商品按钮自动禁用。
- 已加入的商品卡会高亮描边并显示「已在购物车：N 件」，页面底部浮出**吸底购物车条**（款数、预估合计、清空、去结算），移动端自动换行。
- 购物车以 Cookie（`jc_cart`，`[[商品ID, 数量], ...]`）保存，最多 30 行、30 天有效；**不写 D1**，退出登录自动清空，避免换账号串单。
- 价格仅用于前端预估展示，结算时一律以数据库实时售价与库存为准。

### 2. 自助下单页（`/shop`）明细改造
- **移除「＋ 添加商品行」按钮**：客户不再手工增行，避免一单多行同商品绕过库存校验。
- **「＋ 继续添加商品」改为跳转商品目录**（`<a href="/catalog">`），形成「目录选购 → 购物车 → 结算」闭环。
- 购物车中的商品在进入下单页时由服务端直接渲染为明细行（数量、单价、行小计预填），并给出「已带入 N 款商品」提示；下架/缺货、超库存数量会被自动移除或按库存上限调整并提示。
- 明细行删除按钮同步移除购物车对应商品；**提交成功后服务端清空购物车 Cookie**，避免重复下单。
- 客户视角单价输入框只读；`POST /shop` 忽略前端提交的 `price`，强制按商品标准售价结算（修复客户可篡改单价下单的越权风险），并新增空明细拦截。

### 3. 客户收货信息完善页升级
- 个人中心顶部新增**完善进度卡**：收货人姓名 / 联系电话 / 详细地址 三项清单 + 进度条，未完善时黄色「待完善」，完善后转为绿色「已完善」并直接给出「去商品目录选购」「自助下单」入口。
- 收货信息表单新增「🛍️ 保存并去商品目录 →」按钮（`next=catalog`），与「保存并前往下单」并列，贴合「先完善资料再挑货」的真实动线。
